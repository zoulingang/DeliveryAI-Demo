## 1. 一句话概述

在现有火锅门店点单概念演示应用中增加双币种（CNY/USD）价格展示与切换能力，使用户能够在界面上自由选择以人民币或美元查看所有价格项，同时仅改变展示币种、不影响底层数据准确性。

## 2. 背景与目标

### 背景

- 当前应用所有商品价格均以人民币（¥）存储和展示，`money()` 函数硬编码 `¥` 符号，无币种概念。
- 应用已具备中/英双语切换、暗黑/浅色主题切换、老人模式等偏好设置能力，均在 TopBar 中提供切换入口。
- 需求要求增加美元（USD）币种展示，使用固定汇率 1 USD = 7 CNY 进行换算，满足多币种场景下的价格展示需求。

### 目标

1. 用户可在界面上自由切换查看币种（CNY ↔ USD），切换后全站价格即时以选中币种展示。
2. 价格展示同时支持人民币符号（¥）和美元符号（$）。
3. 汇率固定为 1 USD = 7 CNY，切换后所有价格项按此汇率实时换算。
4. 切换币种不影响底层数据准确性（商品价格、购物车金额、折扣计算等仍以 CNY 为基准）。

### 不做

- 不引入实时汇率获取或第三方汇率 API（固定汇率 1:7）。
- 不支持除 CNY、USD 之外的第三方币种。
- 不改变后端服务（后端仅有 `/ping` 健康检查，无价格逻辑）。
- 不改变商品数据的存储币种（数据层始终保持 CNY）。
- 不修改支付流程逻辑（支付仅为模拟，不涉及真实交易）。
- 不做双币种同时并排展示（同一时刻仅展示一种币种）。

## 3. 需求详情

### 用户场景

- **场景**：顾客在火锅门店点单概念演示应用中浏览菜单、查看购物车、跟踪订单、结账时，希望以自己熟悉的币种（CNY 或 USD）查看所有价格信息。
- **典型用户**：中文用户默认看到人民币价格；有英文/美元使用习惯的用户可切换至美元查看。

### 用户路径

1. 用户进入应用，默认以人民币（¥）展示所有价格项（菜单价格、购物车金额、订单总额、结账金额等）。
2. 用户通过 TopBar 中的币种切换入口选择目标币种（CNY 或 USD）。
3. 切换后，全站所有价格项即时以选中币种符号和换算后的金额展示。
4. 用户继续浏览菜单、加购、查看订单、结账，所有流程中价格均以选中币种显示。
5. 用户可随时再次切换币种，价格即时更新。

### 产品规则

1. **展示模式**：同一时刻仅展示一种币种（CNY 或 USD），通过切换入口选择，不做双币种同时并排展示。（已确认）
2. **默认币种**：首次进入应用时默认展示人民币（CNY）。（已确认）
3. **汇率规则**：固定汇率 1 USD = 7 CNY。CNY → USD 换算公式为 `USD = CNY / 7`。
4. **换算精度**：换算后金额保留两位小数，四舍五入。
5. **数据层不变**：商品数据、购物车、订单、折扣计算等均以 CNY 为基准，币种切换仅影响展示层。
6. **折扣规则换算**：结账页"满 100 减 30"优惠规则在 USD 展示模式下，门槛和优惠金额按汇率换算显示（即门槛 ≈ $14.29，优惠 ≈ $4.29），底层数据判断仍以 CNY 为准。（已确认）
7. **优惠券文本换算**：会员区"含 ¥30 菜品券"文案中的金额随币种切换换算。（已确认）
8. **切换入口**：在 TopBar 中提供币种切换入口，与语言切换、主题切换并列。
9. **币种偏好持久化**：用户的币种选择通过 localStorage 持久化，刷新后保持。（已确认）

### 状态与反馈

- **成功**：用户切换币种后，全站所有价格项即时更新为选中币种的符号和换算金额，无页面刷新。
- **失败**：本需求为纯客户端展示逻辑，无网络请求，不涉及失败重试场景。
- **空态**：不适用（币种切换与数据空态无关联，空购物车仍显示 ¥0.00 或 $0.00）。
- **无权限**：不适用（所有用户均可切换币种，无权限控制）。
- **异常**：localStorage 不可用时降级为内存态，不报错不阻塞（与 useTheme 一致）。
- **保持不变**：商品数据、订单状态机、支付流程、主题/语言/老人模式等既有功能不受币种切换影响。

### 关键文案

- 币种切换入口：需提供 CNY / USD 两个选项的切换控件。（具体文案待设计阶段确定）
- 人民币格式：`¥X.XX`（保持现有格式）
- 美元格式：`$X.XX`

### 关键表现要求

- 切换币种后价格更新应为即时响应，无明显延迟。
- 币种切换入口应与现有 TopBar 控件视觉风格一致，不干扰主操作区。

## 4. 约束限制

- **实现边界**：仅在现有前端 SPA 架构内实现，不引入新依赖、不改后端。
- **数据层约束**：商品价格数据（`src/data/menu.ts`）始终保持 CNY，换算在展示层完成。
- **兼容要求**：不破坏现有的中/英双语 i18n 系统、暗黑/浅色主题、老人模式等既有功能。
- **性能要求**：币种切换不应增加明显渲染延迟，所有价格项应同步更新。
- **稳定性要求**：localStorage 不可用时降级为内存态，不报错不阻塞。

## 5. 验收标准

- [主流程] 在应用已加载且展示价格的前提下，用户通过 TopBar 币种切换入口选择 USD 后，全站所有价格项（菜单价格、购物车金额、订单总额、结账金额）应在 1 次渲染周期内即时更新为 `$` 符号和按 1:7 汇率换算后的金额。
- [主流程] 在 USD 模式下用户再次选择 CNY 后，全站价格应恢复为 `¥` 符号和原始 CNY 金额。
- [内容正确性] USD 金额 = 对应 CNY 金额 ÷ 7，保留两位小数四舍五入；例如 ¥68 应显示为 $9.71。
- [内容正确性] 结账页折扣门槛和优惠金额在 USD 模式下按汇率换算显示（满 $14.29 减 $4.29），底层数据判断不变。
- [内容正确性] 会员区"含 ¥30 菜品券"在 USD 模式下应显示换算后的美元金额（$4.29）。
- [边界约束] 切换币种不应影响商品数据、订单状态、支付流程、主题/语言/老人模式等既有功能。
- [兼容稳定] 币种偏好通过 localStorage 持久化，刷新页面后保持上次选择；localStorage 不可用时降级为内存态，不报错。
- [异常处理] 刷新页面后默认恢复上次币种选择（如有 localStorage），否则默认为 CNY。
